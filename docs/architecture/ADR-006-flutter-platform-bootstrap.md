# ADR-006: Generate Flutter Platform Templates Locally

- **Status:** Accepted
- **Date:** 2026-07-18

## Context

Flutter-generated Android, iOS, Web, Windows, macOS, and Linux templates change
between Flutter releases. Committing templates generated by an unknown SDK
would create avoidable build drift for a new frontend that did not previously
contain platform folders.

## Decision

Commit Astra-owned Dart source, tests, configuration, and bootstrap scripts.
On first setup, generate platform folders using the developer's installed
stable Flutter SDK in a temporary directory, then copy only platform folders
and `.metadata` into `frontend/`.

The Windows bootstrap creates Android, Web, and Windows targets. macOS/Linux
scripts create targets supported by their host. Android cleartext access is
enabled only in the debug manifest for the local HTTP backend; production must
use HTTPS.

## Alternatives

### Commit platform folders generated in the build environment

Rejected because the artifact environment does not contain Flutter and must not
invent version-specific native templates.

### Require developers to run `flutter create .` directly

Rejected because it may overwrite Astra-owned files and is harder to review.

## Consequences

- Native templates match the installed Flutter SDK.
- A one-time bootstrap command is required.
- Generated native files should be reviewed and committed after bootstrap.
- CI must run code generation before analysis and tests.
